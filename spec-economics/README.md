# spec-economics — what a weak spec costs, measured

One feature. Two specs. Same model, same starting stub. This experiment runs
Claude Code twice — once with a **realistic vague ticket**, once with a
**well-designed spec** (EARS criteria + an executable contract) — and prints
what each condition consumed in **tokens, dollars, wall time and review
rounds**. It turns the webinar's slide-4 claim into a number you can screenshot:
*a wrong spec is regenerated at machine speed, and every retry re-bills the
same ambiguity.*

## The feature

`applyDiscount(subtotalCents, code, catalog, now)` — discount codes for a
checkout. Chosen because it's small but *packed* with silent decisions:
rounding of percentage discounts, clamp-vs-reject below zero, discount caps,
code case-sensitivity, expiry semantics, minimum-order handling, error shapes,
money representation. Eight decisions; the weak ticket makes zero of them.

## The two prompts (read them — they're the whole experiment)

- **`prompts/weak-spec.md`** — the ticket as it actually arrives: *"percentage
  and fixed codes… expiry… big codes shouldn't give crazy discounts… handle
  bad codes gracefully… make it robust."* Every requirement present in
  spirit, none decided.
- **`prompts/strong-spec.md`** — the same feature after one honest refinement
  hour: EARS-1…8 (each one testable), the exact function signature and return
  shapes, the check order, an Out-list — and the contract test file handed
  over up front, with "run `npm test` until green" as the definition of done.

## The referee: a hidden oracle

`test/oracle.test.mjs` encodes **the stakeholder's actual intent** as eight
executable asserts (verified satisfiable — `solution/discount.solution.js`
passes 8/8; the stub fails 8/8).

- **Strong run:** the oracle is *given* to the agent as
  `test/contract.test.mjs`. That's not cheating — **that is the method**: in
  SDD the contract exists before implementation. One session, done.
- **Weak run:** the oracle stays hidden — it plays the human reviewer. When
  the agent declares "done", the harness runs the oracle out-of-band; failures
  come back as a stakeholder-review message ("expected 1235, got 1234…"), and
  the session resumes. Each round is one real-world rework cycle, and its
  tokens/cost/time are added to the bill. Cap: `MAX_ROUNDS` (default 5).

**Fairness note, said out loud:** the strong condition contains more input
text (the spec + the tests), so its *first* round costs slightly more input.
The experiment's claim is that this bounded upfront cost deletes the unbounded
retry cost — exactly the slide-5 verdict. The numbers decide.

## One command

```bash
./demo.sh --offline    # rehearsal: zero API calls, recorded sample runs, full statistics
./demo.sh              # live: runs Claude Code twice, prints YOUR numbers
```

Five visible steps: the feature and its eight silent decisions → the two specs
side by side → the executable referee → both runs → the statistics table with
a per-round breakdown of the weak run (rounds 2+ are pure ambiguity tax).

## Run it

```bash
# prerequisites: claude (Claude Code, authenticated — API key or Bedrock), jq, node ≥ 20
./run-experiment.sh                      # both conditions + report
MODEL=claude-sonnet-4-6 MAX_ROUNDS=5 ./run-experiment.sh   # knobs
npm test                                 # (in a run dir) the contract/oracle
node scripts/report.mjs runs/weak/results runs/strong/results
```

Everything lands in `runs/{weak,strong}/` (isolated copies — the agent in the
weak run cannot see the oracle) and the table in `results/report.md`.

## Showing it to an audience

1. **Before:** open both prompt files side by side — thirty seconds of silent
   reading makes the point before any number does.
2. **During (optional, live):** run the two conditions in two terminals with
   `--output-format stream-json` for the matrix-rain effect; or run beforehand
   and skip the wait.
3. **After — the reveal:** show `results/report.md`. The headline line is
   pre-written by the report script:

   > *Headline: the strong spec finished in 1 round using 8.5× fewer tokens,
   > 6.4× cheaper and 4.9× faster than the weak spec.*

   (Those figures are from `results/example-report.md`, generated by the real
   report script over **sample** fixtures in `results/sample/` — clearly
   labeled; your live numbers will differ, and that's the fun. Typical shape:
   weak = 3–5 rounds; strong = 1.)
4. **The sentence to land:** "Every weak-spec round after the first is the
   price of one ambiguity — paid in tokens, dollars and minutes. The strong
   spec paid for those decisions once, in words."

## What each measured column means

- **Rounds to stakeholder-green** — how many review cycles until the hidden
  intent was satisfied. The direct cost of undecided decisions.
- **Fresh input / cache read / output tokens** — what the API actually billed;
  cache reads are cheaper but not free, and the weak run's re-reads of the
  growing session are where its bill explodes.
- **Cost (USD)** — straight from Claude Code's `total_cost_usd`, summed.
- **Wall time** — summed `duration_ms`: the human minutes spent waiting.

```
results/sample/ · example-report.md      offline demonstration of the pipeline
```

Verified offline in a clean container: oracle 8/8 green on the solution and
0/8 on the stub; harness and report syntax; the example report is the real
script's real output over the sample fixtures. Needs your machine (network):
the two `claude` runs themselves. Flags live at the top of `run-experiment.sh`
— reconcile with `claude --help` if your Claude Code version differs.
